# Adobe / CES — Leadership / Stakeholder Update

Used for updates to CES management, cross-org stakeholders, or any audience above the team level.

**Audience:** CES managers, directors, cross-org leads  
**Tone:** Outcome-focused, brief, assumes some but not deep technical context

## What to gather

- **Purpose**: What is this update communicating? (project status, escalation, decision request, FYI)
- **Key outcomes**: What has been achieved or decided?
- **Current status**: Where do things stand right now?
- **Risks or blockers**: Anything leadership needs to know or act on?
- **Ask (if any)**: Do you need a decision, approval, or unblocking?

## Format

```
**[Subject / Project Name] — Update [Date]**

**Status:** [On track / At risk / Blocked / Complete]

**Summary**
[2–3 sentences: what this is, where it stands, what matters]

**Progress**
- [Key accomplishment]
- [Key accomplishment]

**Next Steps**
- [What happens next, with owner and date]

**Risks / Blockers**
- [Issue] — [Impact if unresolved] — [What's needed]

**Ask** *(if applicable)*
[Specific decision or action needed from leadership, with deadline]
```

## Guidance

- Open with the status signal — leadership should know if something is red before reading the details
- Every "blocker" must state the impact of not resolving it — urgency without context is ignored
- If there's an "ask", make it the most prominent thing in the message
- Avoid technical acronyms unless the audience uses them regularly (Vault is fine; OIDC, KV2 probably aren't without context)
- Length: if it takes more than 2 minutes to read, it's too long for a leadership update
